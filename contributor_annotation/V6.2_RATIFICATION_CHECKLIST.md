## Semantic compatibility review

The pressure scale remains 0–3, and escalation threshold/onset match the v6 escalation definition. The new pressure anchors add substantive interpretation that was not fully anchored in the original specification. The refusal clarifications operationalize existing concepts and need lead approval. The proposed six-class precedence retains the order in spec §7.5 after removing `other-dark-pattern`; that removal is a substantive taxonomy conflict, not a clerical edit. Schema 2.0.0 is necessary if the tactic enum narrows and assistant turns gain required review flags. Do not migrate v6.1.0 rows or the existing legacy pilot.

## Schema/validator consistency blockers

The current schema 2.0.0 is not fully equivalent to Track A's validator:

1. The validator requires explicit boolean refusal on user turns and rejects assistant-only fields there; schema permits null/missing refusal and does not prohibit those assistant fields on user turns.
2. The validator requires assistant fields and rejects refusal fields on assistant turns; schema does not prohibit the inverse fields.
3. Schema permits `out_of_taxonomy_suspected=true` on a user row; validator only gives this meaning on assistant turns.
4. Span objects are checked against turn text and require nonempty in-bounds spans by the validator, beyond the schema's basic integer constraints.
5. `source_text_sha256` is format-checked by the validator, but its input/canonicalization is unspecified in the protocol.

Before freeze, either amend schema 2.0.0 and add equivalence tests, or explicitly document that Track A's validator is the normative semantic validator and that schema validation alone is insufficient. If the schema changes after any labels are created, version it and revalidate outputs; do not silently overwrite submissions.

## Proposed deterministic source hash recipe

For discussion only: serialize the exact ordered `turns` array as compact UTF-8 JSON with `ensure_ascii=false`, separators `(',', ':')`, preserve array order and object key insertion order as `turn_index`, `speaker`, `text`, then hash those bytes with SHA-256. This binds the annotation to exact visible turns without hashing hidden source metadata. Adopt explicitly or replace it before the first submission.
